# Contract: `rune ci` commands

## `rune ci`

```text
rune ci                 # the note below when the Runefile has a task named ci, then help; exit 0
rune ci deploy          # usage error: unknown command "deploy" for "rune ci"; to run a task named ci, use: rune -- ci   (exit 2)
```

Note, on standard error, when the Runefile found from the working directory has a task
named `ci`:

```text
note: "ci" is also a task of this Runefile; run it with: rune -- ci
```

## `rune ci github`

```text
rune ci github [flags] ROOT [ARG...] [ROOT [ARG...]]...
```

| Flag | Meaning |
|---|---|
| `-f, --file PATH` | use this Runefile |
| `--os OS` | `linux` (default) or `macos`; repeatable |
| `--rune-version V` | the release the jobs install; default: this rune, when it is a release |
| `--branch NAME` | the branch whose pushes run the workflow; default `main` |
| `--write` | write `.github/workflows/rune.yml` in the Runefile's directory |
| `-o, --output PATH` | write PATH instead |
| `--check` | compare the target with what a write would produce; write nothing |

`--check` and `--write` together are a usage error. `--check` with `--output` checks that
path.

### Output

- No `--write`, `--output` or `--check`: the workflow on standard output; on standard error
  `N jobs for M root tasks on OS[, OS]`.
- Write: standard error `PATH: created|updated|unchanged: N jobs for M root tasks on OS`.
- Check: standard error `PATH: current|stale|missing|not generated by rune ci github`, and
  when not current `regenerate with: COMMAND`.

PATH is shown relative to the working directory when it is below it.

### Errors

| Case | Message (standard error) | Exit |
|---|---|---|
| no root | `rune ci github needs the tasks CI runs: rune ci github TASK...` | 2 |
| unknown task | as `rune` reports an unknown task | 2 |
| `NAME=value` | `rune ci github does not take variable overrides: a job could not repeat NAME=value` | 2 |
| `--os windows` or other | `--os: windows runners are not supported; use linux or macos` | 2 |
| development build, no `--rune-version` | `this rune is a development build; name the release the jobs install with --rune-version` | 2 |
| bad version | `--rune-version: "x" is not a release version such as 0.11.0` | 2 |
| version below `minimum_version` | `--rune-version 0.9.0 does not satisfy minimum_version 0.10.0 of the Runefile` | 2 |
| `--branch` with `${{` or a control character | `--branch: ...` | 2 |
| target not generated by Rune | `ci github: PATH was not generated by rune ci github, so it is not replaced; nothing written` | 2 |
| Runefile not valid | diagnostics | 3 |
| a refused construct (research R5) | a diagnostic at the task, attribute, expression or body line, e.g. `task "deploy" has [confirm]: CI cannot ask a person; run it by hand` | 3 |
| stale or missing on `--check` | `ci github: PATH is not current` | 1 |
| file cannot be read or written | the OS error with PATH | 1 |

## `rune ci run`

```text
rune ci run [-f PATH] [--dir DIR] [--key] [--] TASK [ARG...]
```

Runs the body of exactly one task with these arguments, as `rune TASK ARG...` runs it, but
without its dependencies and post-hooks. Its failure hooks run when the body fails, as
locally.

- `--dir DIR`: before the body, unpack `DIR/in/*/bundle.tar` in name order, then
  `DIR/bundle.tar` when present. After a successful body of a `[cache]` task, write
  `DIR/bundle.tar` (outputs and cache record).
- `--key`: needs a `[cache]` task. Unpack `DIR/in` when `--dir` is given, print
  `key=rune-<slug>-<64 hex>` on standard output, run nothing.

| Case | Exit |
|---|---|
| body succeeded (or a cache hit) | 0 |
| body failed | the code `rune TASK` exits with |
| interrupted | 130 |
| `--key` on a task without `[cache]` | 2 |
| unknown task, bad arguments | 2 |
| Runefile not valid | 3 |
| a bundle that cannot be read, holds an unsafe entry, or cannot be written; a fingerprint that cannot be computed | 1 |
